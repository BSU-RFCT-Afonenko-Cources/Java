# Исследовательские рефераты по Core Java

Подпроект составного курса Quarto: 60 тем в 12 тематических разделах и открытый демонстрационный комплект. Семестр и сложность задаются в метаданных реферата; номера глав создаёт Quarto. Каталоги используют смысловые имена без порядковых номеров.

## Работа с книгой

Используются актуальные стабильные Quarto и CUE. Расширения находятся в репозитории и не скачиваются при сборке. Запускайте команды из корня курса:

```sh
quarto render --profile student
quarto render --profile full
quarto preview --profile student --no-browser --port 4200
```

Корневая сборка согласует книгу и рефераты, разрешает ссылки `@book:…` и
`@essay:…`, проверяет учебную модель через CUE и создаёт стартовые ZIP-архивы.
Студенческий сайт находится в `_site-student/`, полный — в `_site-full/`;
рефераты в обоих случаях размещаются в `essay/`. Публикуйте студенческий сайт.
Самостоятельный рендер каталога `essay/` не разрешает ссылки на книгу, поэтому
для работы с рефератами используется та же корневая команда.

Видимость относится к результату сборки, а не к доступу к GitHub. В публичном репозитории исходные условия контроля, авторские решения и тесты доступны читателям репозитория. Для конфиденциальных контрольных исходники нужно хранить в репозитории с ограниченным доступом.

## Авторский формат

В каталоге раздела находится вводный `index.qmd`; в каталоге отдельного реферата — описание `index.qmd`, включаемый `_control.qmd` и проверочные проекты. `categories` содержит отдельные тематические теги. Оглавление задаёт `_quarto.yml`, указатели по семестрам и сложности строятся из метаданных глав.

### Метаданные задания и подготовка

Сложность хранится один раз, в YAML главы. Поле использует общие значения Core:

| Метаданные `difficulty` | Принятый уровень | Смысл в этом курсе |
|---|---|---|
| `introductory` | У1 | Один основной контракт |
| `intermediate` | У2 | Несколько правил и граничных случаев |
| `advanced` | У3 | Взаимодействие компонентов или гарантий среды |

Например:

```yaml
semester: 1
difficulty: intermediate
```

Настройка `course-pedagogy.document-defaults: true` позволяет `course-core` читать
`difficulty`, `time` и `work-mode` из метаданных документа и применять их как
значения по умолчанию для упражнений. Атрибуты конкретного упражнения имеют
приоритет. Нативные указатели Quarto читают то же поле `difficulty`; отдельной
таблицы сложности и дополнительных блоков оформления нет. Общий `work-mode: individual`
соответствует индивидуальной защите, описанной во введении.

`time` — необязательная оценка трудоёмкости в целых минутах. Она не запускает
таймер и не задаёт лимит защиты. В существующих темах время не проставлено:
продолжительность защиты объявляет преподаватель.

Общая подготовка каждого тематического раздела хранится в одном
`_prerequisites.qmd`. Главы подключают её стандартным `include` внутри задания:

```markdown
:::: {#exr-essay-topic target="manual"}
## Содержание исследования

{{< include ../_prerequisites.qmd >}}

Исследовать …
::::
```

Файл подготовки содержит обычный Pandoc Div и ссылки Quarto Reference Catalog:

```markdown
::: {course-role="prerequisites"}
- Числовые преобразования: @book:sec-java-types-numbers-conversions.
:::
```

Вложенный блок относится к окружающему упражнению автоматически. Подготовка
обозначает необходимые знания, а не автоматический допуск или необходимость
сдать другую работу. Для дополнительной подготовки по отдельной теме можно
добавить ещё один такой Div: примеры есть в `integer-promotions` и
`charset-decoding`.

### Логические блоки и раскрытие ответа

`course-core` извлекает смысл и проверяет метаданные. `course-presentation`
отображает блоки через стандартные элементы Quarto. Тема HTML остаётся `cosmo`;
фирменный стиль и навигация не нужны для работы учебной разметки.

Открытая тема `text-arrays/unicode-demonstration` показывает демонстрацию,
прогноз, обсуждение и самопроверку. Вопросы прогноза и самопроверки имеют нативные
ID `exr-*`, но не имеют `target`, поэтому не добавляются к оцениваемым заданиям
или контрольным. Их объяснения используют стандартные `sol-*` и связь `for`:

```markdown
::: {#sol-essay-unicode-prediction for="exr-essay-unicode-prediction"}
Объяснение …
:::
```

В HTML объяснение свёрнуто для самостоятельной работы. В лекции Reveal.js оно
появляется по обычной команде перехода вперёд. При печати и экспорте PDF видимые
в выбранном профиле блоки раскрываются. Это поведение не меняет видимость
`.when-full` и не публикует преподавательские материалы в студенческой версии.

Требования к сдаваемому реферату и критерии защиты во введении выделены ролями
`deliverables` и `criteria`. Ссылки для подготовки в демонстрационной теме и
`charset-decoding` используют `reading` с `requirement="recommended"`. Эти роли
описывают содержание и сохраняются независимо от оформления.

Преподавательский материал помещается в компактный блок:

```markdown
::: {.when-full}
Материал преподавателя.
:::
```

Общие число попыток и порог зачёта описаны один раз в `_quarto.yml`. Состав контрольной задаётся ссылками `.assessment-items`. Метки назначения производны от устойчивых ID, а не от номеров глав или путей.

## Исполняемые комплекты

- `failures-boundaries/charset-decoding/`: три задания по обработке UTF-8, стартовые проекты, авторские решения и автоматические проверки.
- `text-arrays/unicode-demonstration/`: открытая демонстрационная тема с тремя заданиями. Они используют `target="manual"`, не включаются в контрольные PrairieLearn и доступны со стартовыми архивами.

Остальные темы содержат описания и проекты условий контроля; их каталоги проектов пока служат местами будущей реализации. Сборка книги проверяет авторский контракт, но не превращает эти наброски в готовые исполняемые задания.

Каждый реализованный проект содержит самостоятельный Gradle-проект в `student/`, авторские файлы в `reference/` и дополнительные проверки в `tests/`. Например:

```sh
cd failures-boundaries/charset-decoding/projects/implementation
# Работа со стартовым проектом:
gradle -p student test
# Проверка авторского решения полным набором тестов:
gradle -p student -Preference -Pgrading test
```

Версия Java для исходников и зависимости тестов зафиксированы в настройках каждого проекта. Неполный стартовый код должен компилироваться; часть тестов до выполнения задания закономерно не проходит.

Шорткод `{{< project-download exr-id >}}` создаёт архив из `student/` проекта указанного упражнения. ZIP формируется при сборке и не хранится в Git. Папки `reference/` и `tests/` в него не входят. Условия задач остаются в QMD; отдельные `question.html` или копии условий не редактируются.

Экспортёр полного курса PrairieLearn в этой редакции не реализован. `target="prairielearn"` и состав контрольной описывают будущую поставку на платформу; серверное назначение вариантов является отдельной операцией.

## Включение в общий сайт

В составном курсе добавьте подпроект в `reference-catalog.projects`, например `essay: {path: essay, format: html}`. Его можно сделать начальной страницей через `home: essay`. Письменные задания из `test/` собираются отдельно в PDF.
